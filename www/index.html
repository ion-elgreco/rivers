Orchestration that runs at Rust speed.

Define pipelines in Python. rivers resolves the graph, plans execution, and runs the scheduler in compiled Rust — with no Python interpreter on the control plane.

Get started View on GitHub
$ pip install rivers
pipeline.py
import rivers as rs

@rs.Asset
def raw_data():
    return {"users": 100, "events": 5000}

@rs.Asset
def summary(raw_data: dict):
    return f"{raw_data['users']} users"

repo = rs.CodeRepository(assets=[raw_data, summary])
repo.materialize()

rivers reads the type-annotated parameters and builds the dependency graph. No wiring step.

Everything a data platform needs

Built in, not bolted on.

◆ Asset-based orchestration

Declare data assets as Python functions. rivers resolves the dependency graph from the signatures, and supports single, multi-output, graph, and external assets.

Assets →

▦ Partitions that scale

Static, time-window, multi-dimensional, and dynamic partitions. Partition mapping and key validation run in Rust, so large partition sets stay responsive.

Partitions →

⚙ Executors for any scale

Run in process while you develop. Switch to concurrent subprocess workers, or give every step its own Kubernetes pod, without changing your asset code.

Executors →

◷ Schedules, sensors, automation

Declarative triggers — cron, event-driven, and dependency-aware automation conditions — evaluated by the rivers daemon.

Automation →

↻ Backfills and retries

Run partition ranges with multi-run, single-run, and per-dimension strategies. Declarative retries match on exception type and classify infrastructure failures.

Backfills →

▤ Persistent storage built in

Embedded SurrealDB with RocksDB for local development. A SurrealDB server for production. Run history, lineage, and logs are durable from the first run.

Python is the API.
Rust does the work.

Graph resolution, partition mapping, execution planning, and the scheduler are all compiled Rust. Python is the surface you write against, and nothing more.

Plan times stay below a millisecond on graphs with thousands of nodes.

Read the architecture
  • Graph resolution in petgraph, not Python objects
  • One binary starts the database, scheduler, and UI
  • Server-sent events push run state to the browser
  • No control-plane Python interpreter to keep warm

Kubernetes-native

rivers ships an operator and custom resource definitions. Declare a repository as a CodeLocation and the operator reconciles it.

Install on Kubernetes
codelocation.yaml
apiVersion: rivers.io/v1alpha1
kind: CodeLocation
metadata:
  name: analytics
spec:
  image: ghcr.io/acme/pipelines
  tag: v0.2.0
  module: pipelines.analytics
